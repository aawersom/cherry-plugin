# Cherry — План комплексной проверки (стриминг + UI/UX), с эмуляцией всех кейсов

**Дата:** 2026-06-10 · **Режим:** план (артефакт) · **Цель:** воспроизводимо и точно проверять
поведение плагина на двух уровнях — **стриминг** (каталог→стрим→воспроизведение) и **UI/UX**
(навигация D-pad, грид, меню, состояния) — на двух платформах (**браузер** lampa.mx и **Android TV**),
без ручного тыканья в телевизор по каждому каналу.

Принцип: симптомы вроде «не играет / медленно / низкое качество / пустые карточки / чузер»
ловятся ДО устройства — эмулятором на уровне URL/маршрутизации/достижимости, а то, что требует
реального плеера/IP — отдельным device-чек-листом. Анти-оверинжиниринг: переиспользуем
существующее (`test/android-emu.cjs`, vitest, `test/channel-health.mjs`), наращиваем точечно.

## Фаза 1 — Матрица стриминга (расширить android-emu → полный прогон)

**Зачем:** один прогон должен дать таблицу «канал × платформа × категория × сорт → карточки / URL /
формат / достижимость», чтобы регрессии и сломанные каналы видеть сразу.

**Что построить (`test/stream-matrix.cjs`, на базе android-emu):**
1. **Обе платформы:** параметр `--platform=android|browser` (мокать `Platform.is`); сравнивать ветки
   (где Android отдаёт raw/force-proxy, а браузер — проксирует).
2. **Перебор по каналу:** для каждого из 24 — `browse(cat, page, sort)` по: первой категории, 2-3
   категориям, ПЕРВОМУ сорту, пагинации (page 1→2→3, проверка дедупа `_dedupNew` и роста total_pages).
3. **getStream → классификация URL:** mp4 / m3u8(master vs variant) / protocol-relative⚠ / empty⚠ /
   proxied(host)⚠ / raw. Флагать: пусто, protocol-relative, m3u8-на-Android-без-force-proxy (чузер-риск).
4. **Достижимость стрима (новый этап):** Range-запрос `bytes=0-2MB` на default-URL → статус 200/206 +
   замер throughput; для m3u8 — master→variant→первый сегмент (.ts) цепочкой. Флаг: 404/410/403/таймаут,
   throughput < битрейта (буферизация).
5. **Проверка IP-affinity-пар (статически):** для каждого канала host(страницы) и host(стрима) →
   `buildProxyUrl` тир должен совпадать (или CDN покрыт регексом). Несовпадение = потенциальный 410/буфер.
6. **Качество:** для каналов с лестницей (xvideos/xnxx HLS, youjizz mp4, pornhub) — извлечь доступные
   разрешения/битрейты и дефолт; флаг если дефолт = max на throttle-CDN (как youjizz 1080p) или
   наоборот заведомо низкий (как был xvideos MP4 ≤720p).

**Критерий прохождения:** матрица из 24 строк × {browser, android}; зелёные = карточки>0 + default-URL
достижим (200/206) + тир-пара совпадает; жёлтые/красные перечислены с причиной. Прогон руками/в CI
(сетевой). Отчёт в `tasks/stream-matrix-report.md` (timestamp).

**Известные кейсы, которые матрица обязана ловить (регресс-маяки):**
- pornhub: master.m3u8 отдаётся, но сегменты 404 при ротации SOCKS5 / 410 с VPS → на Android raw
  (device-IP) = рабочий путь; матрица помечает browser-путь как flaky, device-чек-лист подтверждает.
- youjizz: throttle ~1.5× битрейта → дефолт ≤720p (кап); 1080p флагать как «медленный старт».
- xvideos/xnxx: HLS-first (1080p+); если кто-то вернёт MP4-дефолт → флаг «низкое качество».
- hqporner: карточки через force-proxy (VPS), стрим — embed-плеер редизайнут → getStream пусто = RE.
- eporner: getStream hash/xhr пусто = RE; spankbang: только через Val.town (CF-челлендж).
- force-proxy-хосты (hqporner/hellporno/lenporno/eporner/spankbang): на Android страница идёт через
  прокси (не native) — матрица проверяет, что URL проксирован для них и raw для остальных.

## Фаза 2 — Сорты / категории / фильтры / пагинация (функциональная проверка)

**Зачем:** «видео всегда одинаковые» (pornhub) — был баг дефолт-сорта; нужна проверка, что:
1. Каждый канал: `sorts[0]` = осмысленный дефолт (популярное; для pornhub — за неделю), все sorts
   дают РАЗНЫЙ первый экран (сравнить id первых карточек между сортами — не идентичны).
2. Категории: каждая `cfg.categories[i]` возвращает карточки (выявить мёртвые слаги — напр. pornhub
   `ai-straight` отдаёт 0 в эмуляторе → проверить и почистить мёртвые/спарс-категории).
3. Период-композиты (pornhub `mostviewed:weekly/monthly`) → `&ordering=&period=` корректно; weekly ≠
   all-time по контенту.
4. Пагинация: page 2/3 не дублирует page 1 (дедуп `_dedupNew`), `total_pages` растёт пока есть карточки.
5. Модели/студии (где есть: pornhub/xvideos и т.д.) — индексы парсятся, browseBy* отдаёт карточки.

**Как:** расширить матрицу Фазы 1 — для каждого канала прогнать ВСЕ sorts (первая страница) и
N категорий, собрать `{firstCardIds}` и сравнить на различие/непустоту. Отчёт: список мёртвых
категорий/сортов на чистку.

**Критерий:** нет канала с мёртвым дефолт-сортом; список мёртвых категорий → бэклог-чистка.

## Фаза 3 — UI/UX эмуляция (то, что Node-эмулятор не покрывает)

Node-харнес проверяет логику/URL, но НЕ рендер, фокус, D-pad, состояния. Для этого — **Playwright по
lampa.mx в браузере** (10-foot UI там реальный) + клавиатурная навигация (D-pad = стрелки/Enter/Back).

**Что построить (`test/ui-e2e.spec.mjs`, Playwright):**
1. **Загрузка плагина:** инжект plugin.js в lampa.mx (или локальный Lampa), Cherry-меню появляется.
2. **Навигация D-pad:** ArrowRight/Left/Up/Down/Enter/Backspace — фокус движется по гриду/меню;
   **фокус-ринг виден** (скриншот-диф `.card.focus .card__view` scale/box-shadow); нет фокус-ловушек.
3. **Грид:** карточки рендерятся, бейджи (длительность/просмотры/HD-пилюля), превью-dwell (600ms),
   прогресс-бар у просмотренных, `_tileColor` фоллбэк.
4. **Меню сортов/категорий/фильтров:** открытие, выбор, применение, активное состояние (active-выделение
   выбранного), грид перезагружается под новый сорт.
5. **Поиск:** ввод, прогрессивная подгрузка, НЕ виснет (был баг на Android TV) — таймаут-чек.
6. **Похожие (Related):** открывается из плеера и из избранного, скроллится (пагинация), вложенные
   действия работают, нет бесконечного скролла.
7. **История/Продолжить:** просмотр → запись в `cherry_history`, тайл «Продолжить» на home, resume
   позиции (Lampa.Timeline), прогресс-бар.
8. **Состояния:** ошибка → Retry; пусто → empty-state с подсказкой; загрузка → скелетон/Noty.
9. **Home:** буквенные тайлы, `cherry_continue` тайл.

**Критерий:** Playwright-сценарии зелёные; скриншоты ключевых состояний (фокус, меню, ошибка, история)
сравниваются с эталоном (визуальный регресс). Прогон локально; кандидат в CI (headless).

**Опционально (точная Android-эмуляция UI):** реальный Android-эмулятор (AVD Google TV) + ADB —
установить Lampa APK, заскриптовать D-pad через `adb shell input keyevent`, снять `screencap`. Тяжело,
но единственный способ воспроизвести нативный плеер/чузер/IP устройства 1-в-1. Кандидат для редких
«только на устройстве» багов (pornhub-буфер, чузер).

## Фаза 4 — Воспроизведение на реальном плеере (device-чек-лист)

Что эмулятор НЕ может (egress-IP, нативный плеер ExoPlayer, чузер, hls.js): фиксированный чек-лист
для ручного/ADB-прогона на целевых устройствах (Google TV/Sony + один «старый» Android-бокс):

| Проверка | Канал-пример | Ожидание |
|---|---|---|
| HLS играет inline (нет чузера) | xvideos, xnxx | 1080p, без диалога выбора плеера |
| MP4 inline | youjizz, pornone, porntrex | играет, дефолт ≤720p быстро (youjizz) |
| Адаптив/буфер | pornhub | master.m3u8, без вечной буферизации (device residential IP) |
| force-proxy канал | spankbang, hqporner, hellporno | карточки + воспроизведение |
| Качество | xvideos | 1080p визуально (не SD) |
| Сорт-дефолт | pornhub | первый экран = «за неделю», меняется еженедельно |

## Фаза 5 — Непрерывность (CI + scheduled health)

1. **CI (GitHub Actions):** на каждый пуш — `npx vitest run` (быстрые, без сети) + `node --check`.
2. **Scheduled channel-health (cron):** раз в день — Фаза-1 матрица (сетевая) → артефакт-отчёт;
   алерт при росте красных (канал сломался: сайт сменил разметку / IP-блок / квота Val.town).
3. **Регресс-маяки:** anti-drift тесты (как уже есть для px/PROXY-хостов) на каждый «хрупкий» инвариант
   (force-proxy список, HLS-first для xvideos/xnxx, pornhub weekly-дефолт, youjizz ≤720p кап).

## Порядок реализации (когда дашь «делай»)
1. **Фаза 1** (stream-matrix.cjs + достижимость) — наибольшая отдача, ловит 80% стриминг-багов. ~1 проход.
2. **Фаза 2** (сорты/категории/пагинация в матрице) — чистка мёртвых категорий. Встраивается в Ф1.
3. **Фаза 3** (Playwright UI) — отдельный харнес, средняя сложность.
4. **Фаза 5** (CI + cron) — обвязка, быстро.
5. **Фаза 4** (device/ADB) — по необходимости для «только на устройстве» багов.

**Definition of Done всего:** один прогон `node test/stream-matrix.cjs` + `npx playwright test` даёт
полную картину «что работает/сломано» по стримингу и UI без захода на телевизор; красные — с причиной
и адресом (канал/категория/сорт/этап); device-чек-лист — для финального подтверждения IP-зависимого.
