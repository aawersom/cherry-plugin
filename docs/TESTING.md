# Cherry Plugin — Testing Methodology

## Текущая архитектура тестов

```
npx vitest run                      → 47 unit-тестов (mock-based, ~5s)
node test/cherry-lampa-e2e.mjs     → 26 источников в реальном lampa.mx (~10-15 min)
```

### Что делает E2E-тест сейчас

| Шаг | Что проверяется | Что это гарантирует |
|---|---|---|
| Browse → cards | `items.length >= N`, поля `id/source/title/url` | Адаптер возвращает карточки правильного формата |
| getStream × 5 | URL непустой, `urlPresentCount >= 4` | Функция не падает, возвращает ссылку |
| Range-206 | `fetch(bytes=0-65535)` → статус 206 + `Content-Range` | Прокси доставляет первые 64KB с правильными заголовками |
| `loadedmetadata` | `<video>` получает метаданные | Браузер распознал контейнер из первых ~64KB |
| Baseline | Tier A card counts vs. прошлый запуск | Регрессия по количеству карточек |

## Честная оценка пробелов

### Пробел 1 — `loadedmetadata` ≠ воспроизведение (КРИТИЧНЫЙ)

`loadedmetadata` означает: браузер получил первые ~64KB и распознал длительность.  
**Не означает:** видео реально играет. Поток может обрезаться сразу после метаданных и тест не заметит.

```
Текущее: v.addEventListener('loadedmetadata', () => resolve({ ok: true }))
Нужно:   ждать currentTime > 2 (видео реально воспроизводится 2+ секунды)
```

### Пробел 2 — Адаптеры вызываются напрямую, не через UI Lampa

```
Текущее: s.browse('', 1), s.getStream(card) — прямые JS-вызовы
Реальный пользователь: меню Cherry → источник → карточка → кнопка Play
```

На этом пути данные проходят через компоненты Lampa, которые могут трансформировать или дропать поля. Тест проходит, но UI ломается — не поймаем.

### Пробел 3 — Seek не тестируется

Видео начинает играть → пользователь перематывает на середину → сервер должен отдать Range запрос с другого offset. Если токен привязан к offset или CDN не поддерживает произвольный range — перемотка ломается.

### Пробел 4 — Только первый chunk (bytes=0-65535)

Range-206 проверяет только первые 64KB. CDN может отдать первый chunk и обрезать соединение на втором.

### Пробел 5 — Качество не верифицируется

Для источников с quality map (hellporno, pornobolt, pornhub, xvideos и др.) тест проверяет что URL возвращается, но не что:
- Выбирается наивысшее качество
- URL наивысшего качества реально работает (а не только 480p fallback)

### Пробел 6 — Регрессия по формату URL не отслеживается

Baseline хранит только `cardsCount`. Если источник сменил CDN-домен или формат URL — тест не заметит, пока URL не сломается полностью.

### Пробел 7 — KVS-токены (структурный, не решается тестом)

KVS-источники выдают токены, привязанные к IP и TTL ~30-60s. Прокси меняет IP → мismatch. Это архитектурное ограничение: тест либо ложно-красный (тестирует через прокси), либо ложно-зелёный (тестирует без прокси). Подробнее в `docs/CHERRY.md §Known Limitations`.

## Варианты улучшения (ранжированы по ценности/трудозатратам)

### A. `currentTime > 2s` — реальное воспроизведение ★★★★★

**Ценность:** ВЫСОКАЯ — самый частый реальный сценарий отказа  
**Усилия:** НИЗКИЕ — замена одного `addEventListener` + ожидание

**Как:** после `loadedmetadata` не резолвить сразу, а ждать `timeupdate` event с `currentTime > 2`.

```javascript
v.addEventListener('timeupdate', function onTime() {
  if (v.currentTime > 2) {
    clearTimeout(t);
    v.removeEventListener('timeupdate', onTime);
    resolve({ ok: true, dur: v.duration, played: v.currentTime });
  }
});
```

**Ловит:** поток начался, но CDN обрезает после первых байт; буферизация без прогресса; токен истёк после метаданных.  
**Не ловит:** KVS-источники (они всё равно IP-locked через прокси).

---

### B. Seek-тест (перемотка) ★★★☆☆

**Ценность:** СРЕДНЯЯ — важно для длинных фильмов, не важно для clip-источников  
**Усилия:** НИЗКИЕ — добавить после успешного воспроизведения

**Как:** после `currentTime > 2` установить `v.currentTime = v.duration * 0.5`, ждать `seeked` event, проверить `currentTime > v.duration * 0.4`.

**Ловит:** Range запросы с произвольного offset не работают; CDN не поддерживает non-sequential access.  
**Включать:** только для Tier A источников с `videoDuration > 120s`.

---

### C. Второй Range-chunk ★★☆☆☆

**Ценность:** НИЗКАЯ — если A (`currentTime > 2`) уже реализован, это дублирует проверку  
**Усилия:** НИЗКИЕ

**Как:** после `bytes=0-65535` сделать ещё один fetch `bytes=65536-131071`.

**Ловит:** CDN rate-limiting на втором chunk.  
**Решение:** реализовать A, C добавлять только если A не ловит конкретные баги.

---

### D. Верификация качества (quality map) ★★★☆☆

**Ценность:** СРЕДНЯЯ — hellporno, pornobolt, pornhub, xvideos, crocotube имеют quality map  
**Усилия:** НИЗКИЕ — проверить что `bestQualityUrl` действительно выбирает максимум

**Как:** в streamSource добавить проверку:
```javascript
// Если quality map непустой, выбранный URL должен соответствовать максимальному ключу
const maxKey = Math.max(...qk.map(k => parseInt(k, 10) || 0));
const selectedUrl = bestQualityUrl(quality);
// selectedUrl === quality[maxKey + 'p'] или аналог
```

И отдельно: если `urlPresentCount >= 4` для высококачественного URL (а не fallback).

**Ловит:** `bestQualityUrl` выбирает не тот ключ; высококачественные URL возвращают ошибку, плеер фаллбэчится на низкое качество незаметно.

---

### E. Регрессия формата URL ★★★☆☆

**Ценность:** СРЕДНЯЯ — ловит тихие инфраструктурные изменения на стороне сайтов  
**Усилия:** СРЕДНИЕ — нужно хранить паттерны в baseline

**Как:** расширить `cherry-e2e-baseline.json`:
```json
{
  "sources": {
    "hellporno": {
      "cardsCount": 60,
      "streamUrlPattern": "^https://hellporno\\.com/get_file/",
      "streamCdnDomain": "hellporno.com"
    }
  }
}
```

При следующем запуске сравнивать CDN-домен и URL-паттерн. Если сменился — WARNING (не FAIL).

**Ловит:** источник сменил CDN; `get_file/` → другой endpoint; протокол сменился с https на http.

---

### F. Навигация через UI Lampa ★★★★☆

**Ценность:** ВЫСОКАЯ — тестирует реальный путь пользователя  
**Усилия:** ВЫСОКИЕ — TV-UI с клавиатурной навигацией, хрупко

**Как:** Playwright кликает/нажимает Enter через Cherry-меню → источник → карточка → Play. Проверяет что плеер Lampa запустился (ищет `<video>` в DOM плеера, проверяет `currentTime > 2`).

**Проблемы:**
- Lampa-UI заточен под TV-пульт, навигация через `keyboard.press('ArrowDown')` — сложно и хрупко
- Меняется верстка → тест ломается
- Долго (~5 min per source)

**Вывод:** реализовывать только если пробелы A+D не решают проблему. Пока — НИЗКИЙ приоритет.

---

### G. Измерение TTL KVS-токенов (диагностический) ★★☆☆☆

**Ценность:** ДИАГНОСТИЧЕСКАЯ — понять реальный TTL каждого KVS-источника  
**Усилия:** СРЕДНИЕ

**Как:** отдельный тест (не часть E2E): для каждого KVS-источника вызвать `getStream`, затем ждать N секунд и проверить работает ли URL. Измерить при каком N токен умирает.

**Вывод:** полезно для документации (`CHERRY.md`), не для pass/fail. Запускать вручную при добавлении нового источника.

---

## Рекомендуемый порядок реализации

```
Этап 1 (быстро, высокая ценность):
  A — currentTime > 2s вместо loadedmetadata
  D — верификация quality map

Этап 2 (средняя трудоёмкость):
  B — seek-тест для Tier A с длинным контентом
  E — регрессия формата URL в baseline

Этап 3 (только если нужно):
  C — второй Range-chunk (если A не ловит конкретные баги)
  F — UI-навигация (только если A+D+B+E не закрывают реальные баги)
```

---

## Что тест никогда не заменит

- **Проверку на реальном TV-девайсе** — другой браузерный движок, DRM, кодеки
- **Проверку после смены IP** — если CDN блокирует Cloudflare IP, меняет токены
- **Новый аккаунт пользователя** — настройки Lampa могут отличаться

После любой правки адаптера — ручная проверка конкретного источника в браузере на той же машине остаётся обязательной.
