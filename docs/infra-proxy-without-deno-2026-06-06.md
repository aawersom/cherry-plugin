# Cherry — прокси без Deno / без срыва квоты: глубокий разбор (2026-06-06)

Режим medium (анализ+план). Вопрос владельца: как сделать без Deno или так, чтобы квота не пропадала; сколько сейчас на Deno.

## Сколько и что сейчас через Deno

**Листинги через Deno (лёгкий трафик, КБ):** xnxx, youjizz, tizam, pornone, porntrex, spankbang, perfektdamen — **7 каналов**. (eporner — НЕ через Deno: прямой API `_apiFetch`, CORS *.)

**Видео-стрим через Deno (тяжёлый трафик, ГБ — вот это убивает квоту):**
- **pornone, porntrex** — getStream возвращает `buildProxyUrl(mp4)` → весь mp4 течёт через Deno (IP-bound токен KVS).
- **hqporner** — bigcdn/mydaddy mp4 проксируется (regex `\.bigcdn\.cc$` → Deno).
- → всего **3 канала** гонят видеобайты через Deno.

**НЕ зависят от Deno:** остальные ~17 каналов (CF или прямой) — и их **стримы отдаются прямым CDN-URL** (3movs/pornve/familyporn/crocotube/xozilla/analdin/pornobolt/perfektdamen getStream возвращают `{url}` без проксирования) → квоту не трогают.

## Почему вообще нужен Deno (3 РАЗНЫЕ причины)
1. **ASN-блок CF:** xnxx/youjizz/tizam/spankbang/pornhub блокируют IP дата-центров Cloudflare → нужен НЕ-CF IP. (Только страницы, лёгкое.)
2. **IP-affinity токены (KVS):** pornone/porntrex/perfektdamen/bigcdn(hqporner) выдают токен, привязанный к IP, который скачал страницу → страницу И стрим надо тянуть с ОДНОГО стабильного IP. У CF Workers IP «плавающие» → токен бьётся. (Стрим тяжёлый.)
3. **CF-worker SOCKS5 буферизирует** ответ в память (`raw.slice`+`new Response(body)`) → большое видео не протянет (лимит памяти воркера) → поэтому стримы не на CF-SOCKS5.

## Корень срыва квоты
Deno Deploy free ≈ 100 GiB исходящего/мес. **Каждый просмотр pornone/porntrex/hqporner = сотни МБ–ГБ через Deno** → 100 GiB кончаются за часы. Листинги (КБ) — не проблема; убивает именно **видеострим через Deno**.

## Варианты решения (ранжированы)

### ⭐ Вариант A — дешёвый VPS со стабильным IP (рекомендую)
Один маленький VPS (~$4-5/мес: Hetzner CX22 / Contabo / Netcup), стабильный IP, безлимитный/20ТБ трафик. На нём — тот же прокси-код (можно прямо **запустить существующий Deno-скрипт через `deno run`**, без Deno Deploy и его квот; или Node/`gost`/Caddy forward-proxy).
- ✅ Стабильный IP → IP-affinity работает для ВСЕХ KVS (pornone/porntrex/perfektdamen/hqporner).
- ✅ Безлимитный трафик → квота не кончается никогда.
- ✅ Переиспользуем готовый код (`workers/cherry-proxy-deno/main.js`).
- ✅ В плагине меняется ОДНА строка: `PROXY_URL_2 = 'https://<vps>'`.
- ⚠ Datacenter-IP VPS может всё ещё блокироваться xnxx (ASN). Тогда: лёгкие страницы xnxx — через residential SOCKS5 (он у тебя есть), а тяжёлые стримы KVS — через VPS.
- Стоимость: ~$5/мес, настройка ~30-60 мин.

### Вариант B — всё на Cloudflare + residential SOCKS5 (без новой инфры, но сложнее)
CF Workers free **не тарифицирует исходящий трафик** (стриминг через TransformStream бесплатен, лимит 100k запросов/день). Чтобы перенести стримы на CF:
1. Переписать SOCKS5-путь воркера со **стриминга вместо буфера** (`raw.slice`+`new Response` → потоковый разбор HTTP-over-socket + `TransformStream`). Нетривиально.
2. Гнать IP-bound источники через CF+residential-SOCKS5 (стабильный exit по domain-hash — уже есть для pornhub).
- ✅ Нет новой инфры/Deno; CF free покрывает трафик.
- ⚠ Нужен НАДЁЖНЫЙ residential SOCKS5 (комменты: «SOCKS5 unstable / blocks even browse») — а это платный пул + завязано на P0-ротацию утёкших кредов.
- ⚠ Переписать сокет-стриминг воркера — риск средне-высокий.

### Вариант C — гибрид (минимум денег, минимум риска)
- **eporner** уже direct — не трогаем.
- **Листинги ASN-блок (xnxx/youjizz/tizam/spankbang)** — лёгкие; оставить на Deno (КБ, квоту почти не тратят) ИЛИ на residential SOCKS5 через CF.
- **Тяжёлые стримы (pornone/porntrex/hqporner)** — увести с Deno на **VPS** (вариант A только для стримов). Тогда Deno возит только КБ-страницы → квота практически не тратится.
- ✅ Дёшево, точечно. ⚠ Всё равно нужен VPS для стримов (но трафика мало где ещё).

### Вариант D — самохост Deno-кода на VPS
= Вариант A, просто переиспользовать Deno-рантайм (`deno run`) на VPS вместо Deno Deploy. Ноль переписывания, нет квоты Deploy.

## Рекомендация
**Вариант A/D — один VPS со стабильным IP, на нём существующий Deno-скрипт через `deno run`.** Это:
- убирает квоту насовсем (безлимит трафик),
- чинит IP-affinity для всех KVS,
- переиспользует готовый код,
- меняет в плагине 1 строку (`PROXY_URL_2`).
Уже добавленный **Deno→CF failover** остаётся страховкой.

Связка с P0: для xnxx/spankbang/pornhub (ASN-блок) лучше **residential**; если VPS будет с residential-аплинком или ты дашь рабочий SOCKS5 (после ротации) — закроем и их одним узлом.
